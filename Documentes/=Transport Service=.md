## **Transport Service**
### Задачи:
- реестр водителей;
- назначение водителей на транспортные средства (ТС); 
- реестр ТС;
- графики ТО TC;
### Особенности:
- Высокая нагрузка (работа с множеством заказчиков);
- Масштабируемость / Лекговесность;
- Если происходит ЧП с транспортом - то уведомляет сервис доставки;
- Все протоколирует в Reporting Service;
### Стек:
- DB: Postgres;
- Kafka;

---
### Транспортные средства (ТС):
- Добавить новый ТС в автопарк предприятия;
- Получить информацию о ТС/ получить все ТС с пагинацией и без;
- Изменить статус ТС;
  - по занятости (занят в перевозке/ свободен для приема доставки)
  - по тех. состоянию (исправен/ неисправен/ на обслуживании/ в ремонте)
- Удалить ТС из автопарка;

### Водители
- Добавить нового водителя
- Получить информацию о водителе/ всех водителей с пагинауией и без;
- Изменить:
  - Прикрепить/ открепить ТС к данному водителю (у водителя может быть несколько ТС);
  - Статус водителя (работоспособен/ болен-на больничном/ на выходном/ временно неработоспособен)
- Удалить водителя;

### График Тех. обслуживания ТС
- назначить на какой-то день ТО ТС, в этот день данное ТС будет недоступно для бронирования в доставку. Назначается дата в список занятых дат. Передается List занятых дат, можно по одной;
- освоболить ТС от ТО на заданную дату
- получить список:
  - дат ТО для заданного ТС;
  - доступных дат для заданного ТС;
  - список ТС, занятых в ТО на данную дату;
  - список ТС, свободных от ТО на данную дату;
  - количество ТС, занятых в ТО на заданную дату;
  - количество ТС, свободных от ТО на заданную дату;
  - когда было ТО (последнее ТО) данного ТС;
  - когда планируется ТО данного ТС;
- освободить данное ТС от всех ТО;

## Водители:
**Бизнес - правила:** 
- `Driver` — это пользователь с ролью `DRIVER` (это не любой пользователь).    
- Водитель не может управлять своим профилем — только супервизор и выше создаёт/блокирует/ удаляет.
- Водитель может **только читать свой профиль** и менять некоторые настройки (например, статус доступности).

**Бизнес-правила для водителей**
1. **Водитель должен быть подтверждён** (например, права, медосмотр) — поле `verified`.    
2. **Водитель может быть активен или заблокирован** (`active` / `blocked`). Заблокированный не может быть назначен на ТС.    
3. **Водитель имеет тип прав** (категория: `B`, `C`, `CE` и т.д.), который должен соответствовать типу ТС (легковой/грузовой).    
4. **Один пользователь = один профиль водителя** (уникальный `userId`).    
5. **Водитель может сам изменить свой статус** (доступен / не доступен) — `available`.

|Метод|Эндпоинт|Описание|Роль|
|---|---|---|---|
|POST|`/api/v1/drivers`|Создать профиль водителя (из тела). Возвращает объект водителя.|`SUPERVISOR`|
|GET|`/api/v1/drivers/{driverId}`|Получить профиль водителя по ID.|`DRIVER` (только свой), `SUPERVISOR`|
|PUT|`/api/v1/drivers/{driverId}`|Обновить профиль водителя (имя, категория прав и т.д.).|`DRIVER` (себя), `SUPERVISOR`|
|DELETE|`/api/v1/drivers/{driverId}`|Удалить профиль водителя (если нет активных назначений).|`SUPERVISOR`|
|PATCH|`/api/v1/drivers/{driverId}/status`|Сменить статус водителя (`active`/`blocked`).|`SUPERVISOR`|
|PATCH|`/api/v1/drivers/{driverId}/availability`|Сменить доступность (`available`/`unavailable`).|`DRIVER` (себя), `SUPERVISOR`|
|GET|`/api/v1/drivers?category=C`|Список водителей с фильтрацией (по категории, доступности и т.д.).|`SUPERVISOR`|
|GET|`/api/v1/drivers/{driverId}/assignments`|История назначений водителя на ТС (транспорт, дата, длительность).|`DRIVER` (себя), `SUPERVISOR`|

## Назначение водителя:
**Бизнес - правила:** 
- На конкретное заданное может быть назначен только один водитель. 
	  т.е. назначить более 1 водителя на 1 ТС невозможно. 
- На одного водителя может быть назначено только 1 ТС.
	  т.е. водитель не может зарезервировать на себя более 1 ТС

| Метод  | Эндпоинт                                                                                  | Описание                                                                                                      | Роль                                              |
| ------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| PUT    | `/api/v1/transports/{transportId}/assign`                                                 | Назначить пользователя (из тела). Возвращает объект назначения.                                               | `SUPERVISOR` (любого)                             |
| PUT    | `/api/v1/transports/{transportId}/current-user`                                           | Назначить текущего пользователя (без тела). Возвращает объект назначения.                                     | `DRIVER` (только себя), <br>`SUPERVISOR` (любого) |
| DELETE | `/api/v1/transports/{transportId}/assign/{userId}`                                        | Отвязать указанного пользователя от ТС. `userId` обязателен. Тела ответа нет.                                 | `SUPERVISOR`                                      |
| DELETE | `/api/v1/transports/{transportId}/assign/current`                                         | Отвязать текущего пользователя от ТС. Тела ответа нет.                                                        | `DRIVER` (только себя)                            |
| GET    | `/api/v1/transports/{transportId}/assign`                                                 | Узнать, какой пользователь назначен на заданное ТС. Ответ: объект назначения(или `404`, если нет назначения). | `DRIVER` (только себя), <br>`SUPERVISOR` (любого) |
| GET    | `/api/v1/transports/drivers`                                                              | Список всех водителей. Ответ: список id пользователей                                                         | `SUPERVISOR`                                      |
| GET    | `/api/v1/transports/drivers?available=true`/ `/api/v1/transports/drivers?available=false` | Список свободных/ занятых водителей . Ответ: список id пользователей                                          | `SUPERVISOR`                                      |
| GET    | `/api/v1/transports`                                                                      | Список всех  ТС с необязат-й пагинацией. Ответ: список объектов назначения                                    | `DRIVER`, `SUPERVISOR`                            |
| GET    | `/api/v1/transports?assigned=true`/ `/api/v1/transports?assigned=false`                   | Список свободных/ занятых ТС . Ответ: список объектов назначения                                              | `DRIVER`, `SUPERVISOR`                            |


**Тело запроса:**
```json
{
  "userId": "1_234_567"
}
```

**Объект назначения:**
```json
{
  "userId": "1_234_567",
  "role": "DRIVER",
  "transportId": "1_234",
  "assignedAt": "2026-05-06T10:00:00Z"
}
```

**Ответы:**
- `200 OK` — назначение выполнено (или уже было выполнено ранее)   
- `404 Not Found` — транспорт не найден (потому что ресурс назначения не существует)   
- `409 Conflict` — транспорт уже занят (если нельзя пересаживать)    
- `400 Bad Request` — пользователь не существует (если Transport service проверяет)

**Авторизация:**
- `DRIVER` может назначить **только себя** (`userId` из его токена)    
- `SUPERVISOR` может назначить **любого пользователя**
